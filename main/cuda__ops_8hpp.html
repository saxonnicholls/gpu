Detailed Description

snicholls::gpu::cuda_training_backend: snicholls-core's batched training passes on an NVIDIA GPU with every step on the device, so a training step's data stays there.

Overview. Core's batched passes (ml::block_forward_sequence, ml::block_backward and the attention, MLP and linear passes beneath them) make every step a call with their backend (core's TRAINING.md T9): the products, and fill_rows, copy_rows, add_rows, add_bias_rows, sum_rows, mlp_activate_rows and its backward, block_norm_rows and its backward, the four attention steps, and linear_heads with its backward (the keys' and values' projections as one product and a permutation, not one per head). This header overloads each for cuda_training_backend, so with the weights, activations and gradients in device_buffers the whole step runs on the GPU: the products by cuBLAS, the other steps by kernels compiled at run time (NVRTC, to the device's machine code) when cuda_kernels is created.

  • cuda_kernels::create(context): compiles the kernels for the context's device; result with a cuda_failure.
  • cuda_training_backend{{&context}, &kernels}: the backend, two pointers.
auto ctx = gpu::cuda_context::create();
if (ctx.is_err()) {
std::printf("cuda_ops demo: FAILED - no CUDA device\n");
return 1;
}
const auto context = std::move(ctx).unwrap();
auto made = gpu::cuda_kernels::create(*context); // the training steps' kernels, compiled for this device
if (made.is_err()) {
std::printf("cuda_ops demo: FAILED - the kernels did not compile\n");
return 1;
}
const auto kernels = std::move(made).unwrap();
const gpu::cuda_training_backend device{{context.get()}, kernels.get()};
// Every tensor once on the host and once on the device
struct tensor {
std::vector<float> host;
std::unique_ptr<gpu::device_buffer<float>> dev;
};
std::vector<tensor> t;
auto make = [&](std::size_t size, float scale, float offset) {
tensor x{std::vector<float>(size), nullptr};
for (std::size_t i = 0; i < size; ++i)
x.host[i] = offset + scale * std::sin(0.37f * static_cast<float>(i) + static_cast<float>(t.size()));
x.dev = std::make_unique<gpu::device_buffer<float>>(*context, size);
x.dev->upload(x.host);
t.push_back(std::move(x));
return t.size() - 1;
};
const std::size_t n1w = make(d, 0.1f, 1), n1b = make(d, 0.1f, 0), wq = make(d * d, 0.1f, 0), wk = make(d * d, 0.1f, 0), wv = make(d * d, 0.1f, 0),
wo = make(d * d, 0.1f, 0), bq = make(d, 0.1f, 0), bk = make(d, 0.1f, 0), bv = make(d, 0.1f, 0), bo = make(d, 0.1f, 0),
n2w = make(d, 0.1f, 1), n2b = make(d, 0.1f, 0), up = make(f * d, 0.1f, 0), bup = make(f, 0.1f, 0), down = make(d * f, 0.05f, 0),
bdown = make(d, 0.1f, 0), xs = make(n * d, 1, 0), x0 = make(n * d, 0, 0), h1 = make(n * d, 0, 0), x1 = make(n * d, 0, 0),
h2 = make(n * d, 0, 0), q = make(n * d, 0, 0), k = make(n * d, 0, 0), v = make(n * d, 0, 0), y = make(n * d, 0, 0),
lse = make(n * c.n_heads, 0, 0), aup = make(n * f, 0, 0), hid = make(n * f, 0, 0);
auto run = [&](const auto& backend, bool on_device) {
auto s = [&](std::size_t i) { return on_device ? t[i].dev->span() : std::span<float>(t[i].host); };
using W = ml::dense_weights<float>;
ml::block_weights<W> w{};
w.norm1_weight = s(n1w), w.norm1_bias = s(n1b), w.norm2_weight = s(n2w), w.norm2_bias = s(n2b);
w.attention = {W{s(wq), d, d}, W{s(wk), d, d}, W{s(wv), d, d}, W{s(wo), d, d}, s(bq), s(bk), s(bv), s(bo)};
w.mlp = {W{s(up), f, d}, W{}, W{s(down), d, f}, s(bup), {}, s(bdown)};
const ml::block_activations<float> act{s(x0), s(h1), s(x1), s(h2), {s(q), s(k), s(v), {}, {}, s(y), s(lse)}, s(aup), {}, s(hid)};
ml::block_forward_sequence<c>(backend, w, s(xs), ml::no_rope, act);
};
run(device, true); // the norms, residuals, activation and products on the GPU
run(snicholls::linalg::reference, false); // core's reference on the host copies
std::vector<float> got(n * d);
t[xs].dev->download(got);

Relationships. cuda.hpp (the context, the products, device_buffer), core's ml/transformer_block.hpp, ml/attention_layer.hpp, ml/mlp.hpp, ml/linear.hpp (the operations it overloads and the reference it is checked against). Group: snicholls-gpu.

Implementations. The elementwise steps one thread per element; the norms a warp per row (each lane's part of a row's sums in order, then the lanes in a fixed order), the weights' and biases' gradients one thread per column summing the rows in order, so the result does not depend on scheduling; the activations with core's formulas in float. Attention under cuda_math::tf32, for heads of 32 or 64 channels, is flash attention on the tensor cores (mma.sync m16n8k8, TF32 in, float accumulated, as FlashAttention-2 without atomics): the forward a block per (64 queries, head), the online softmax in registers, the log-sum-exp saved, no n x n scores, the tiles past the diagonal or outside a window skipped; the backward one kernel for the queries' gradients and one for the keys' and values' (a block per 64 keys walking the queries that see them, a group's heads in order), both recomputing the probabilities. Otherwise, up to cuda_training_backend::gemm_attention_max tokens (4096), is matrix products head by head, as llm.c's: the scores S = Q Kᵀ through cuBLAS (the tensor cores under TF32), a softmax kernel writing the log-sum-exp, Y = P V; the backward recomputes P from the log-sum-exp and makes the four gradient products, a group's heads adding into its keys' and values' gradients in order. Longer sequences take tiled kernels for heads of 16, 32, 64 or 128 channels: a thread per query or key with its row in registers, the other side through shared memory a tile at a time, the keys' gradients split over the queries into partials added in a fixed order; other head sizes, up to 256, a warp per (token, head). Every path is deterministic. QK norm and RoPE one thread per (token, head), the norms' weight gradients summed in core's order. The kernels' working space (cuda_kernels::scratch) is kept between calls, so a step allocates nothing.

Guarantees. Every step is enqueued on the context's stream, in the order the pass makes them, after the previous product; the results agree with core's reference to rounding (the device's expf, tanhf, sqrtf differ from the host's in the last bits). One training step at a time per context.

Errors. cuda_kernels::create returns a cuda_failure (with the compiler's log on stderr) if the kernels do not compile. A launch or copy that fails throws cuda_exception.

Performance. benchmarks/cuda_ops_benchmark.cpp: a GPT-2-small layer's training step with its data on the device, against the same step staged; see BENCHMARKS.md. A whole GPT-2 small step (124M parameters, sequences of 1024 tokens, forward, backward, clipping and AdamW) on an RTX PRO 4000 Blackwell with nothing else on it, 2026-11-17, with cuda_math::tf32: 68.7 ms at batch 1 and 230 ms at batch 4, against llm.c's 34 and 105 ms in bfloat16; 424 ms at batch 4 in float. At batch 4: the products 131 ms, flash attention 46 ms (115 ms as matrix products), the rest 57 ms.

Tests and demos. tests/cuda_ops_test.cpp (each step against core's, and whole training steps of GPT-2-, Llama- and nanochat-shaped blocks against the reference), demos/cuda_ops_demo.cpp.

Dependencies. cuda.hpp, <nvrtc.h>, core's ml/transformer_block.hpp. Link CUDA::nvrtc too.

Known issues. Float only (the products can be TF32). The attention's products are one call per head; its scores take 3 n² floats of scratch. The tiled kernels for long sequences run on the CUDA cores, not the tensor cores.

Status. Experimental, new in 0.2.0.
