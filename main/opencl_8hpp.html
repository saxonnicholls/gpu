Detailed Description

snicholls::gpu::opencl_backend: a snicholls::linalg::blas_backend whose matrix products run on an OpenCL device, a GPU by preference.

Overview. snicholls-core states the linear algebra interface (linalg::blas_backend) and its reference implementation on the CPU; this header is an implementation on a GPU, through OpenCL 1.2, so code written against core's free functions (linalg::gemm, and through it ml::linear_sequence and the batched training passes) runs on the device with no change but the backend it is handed.

  • opencl_context::create(choice): finds a device (a GPU first, or any OpenCL device), creates its context and queue, and compiles the kernels; result with an opencl_failure when there is none or the build fails.
  • opencl_backend{&context}: the backend, a pointer to the context, trivially copyable as the concept requires. gemm and gemv run on the device; dot, axpy, syrk and triangular_solve run on the host through core's linalg::reference (later versions move them).

Each product copies the spans its views cover to the device, runs one tiled kernel and copies the result's span back, so it pays two transfers: it wins over the CPU only for large enough products (see Performance). Strided views of every layout are read in place; the gaps of the result's span are preserved.

// One context per device, created once: it finds a GPU (or, with device_choice::any, any OpenCL device) and
// compiles the kernels
auto made = gpu::opencl_context::create(gpu::device_choice::any);
if (made.is_err()) {
std::printf("opencl demo: FAILED - no OpenCL device (error %d)\n", static_cast<int>(made.unwrap_err().kind));
return 1;
}
const auto context = std::move(made).unwrap();
const gpu::opencl_backend device{context.get()}; // one pointer: pass it by value
// Y = X Wᵀ for 128 tokens of 256 channels into 512: a transformer's projection, as ml::linear_sequence asks for it
constexpr std::size_t n = 128, d = 256, out = 512;
std::vector<float> x(n * d), w(out * d), on_gpu(n * out), on_cpu(n * out);
for (std::size_t i = 0; i < x.size(); ++i)
x[i] = static_cast<float>(i % 13) * 0.1f - 0.6f;
for (std::size_t i = 0; i < w.size(); ++i)
w[i] = static_cast<float>(i % 7) * 0.05f - 0.15f;
using right = la::layout_right;
const la::matrix_view<const float, right> xv(x.data(), {n, d}), wv(w.data(), {out, d});
const auto gpu_done = la::gemm(device, 1.0f, xv, la::transposed(wv), 0.0f, la::matrix_view<float, right>(on_gpu.data(), {n, out}));
const auto cpu_done = la::gemm(la::reference, 1.0f, xv, la::transposed(wv), 0.0f, la::matrix_view<float, right>(on_cpu.data(), {n, out}));

Relationships. snicholls/core/linalg/backend.hpp (the concept, from snicholls-core), core's linalg::reference (what the device's results are checked against, bit for bit) and its conformance suite (snicholls/core/conformance/linalg.hpp). Group: snicholls-gpu.

Implementations. One kernel for gemm (and gemv as a product with one column): 64 x 64 tiles of the result, 16 deep, in local memory; 16 x 16 work-items each computing 4 x 4 outputs from registers; each tile loaded along its operand's unit stride, so a transposed operand (X Wᵀ, dYᵀ X) is read as fast; each output summed in index order with contraction off (#pragma OPENCL FP_CONTRACT OFF), then alpha s or alpha s + beta c, the reference's arithmetic in the reference's order. double runs on the device when it has cl_khr_fp64, else on the host by the reference.

Guarantees. On a device that keeps IEEE single precision (no flushing of subnormals), gemm and gemv give the reference's bits. One context serves any number of threads: its kernel arguments and enqueues are under one mutex per context. The context owns every OpenCL object and releases them when destroyed; a backend must not outlive its context.

Errors. opencl_context::create returns an opencl_failure (no platform, no device, the program does not build, or another OpenCL call failed, with its code and the build log). A product that fails on the device (out of device memory, a lost device) throws opencl_exception, a std::runtime_error with the OpenCL code: an unexpected failure, so not a result.

Performance. benchmarks/opencl_benchmark.cpp, the device against core's reference on the host, transfers included; see BENCHMARKS.md.

Tests and demos. tests/opencl_test.cpp (core's linalg BLAS conformance suite, the reference's bits, strided and transposed views, threads), demos/opencl_demo.cpp.

Dependencies. <cstddef>, <cstdint>, <memory>, <mutex>, <stdexcept>, <string>, <type_traits>, <vector>, the OpenCL 1.2 headers (<OpenCL/opencl.h> on macOS, <CL/cl.h> elsewhere), snicholls/core/linalg/reference.hpp, snicholls/core/result.hpp. Link OpenCL::OpenCL.

Known issues. Apple has deprecated OpenCL since macOS 10.14 (it still runs, at 1.2); the header silences the deprecation warnings. A device without subnormals (some GPUs flush them) agrees with the reference only to rounding near the bottom of float's range.

Status. Experimental, new in 0.1.0.
