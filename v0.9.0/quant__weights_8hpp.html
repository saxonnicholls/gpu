Detailed Description

snicholls::gpu::block_weights<Block>: a weight matrix of any of ggml's quantised blocks, row by row, as the quantised-weight kernels read it.

Overview. Core's ml::quantized_weights<Block> holds the blocks of 32 that pair with Q8_0 activations (Q8_0, Q4_0, MXFP4). The other ggml formats the device kernels read (Q4_1, Q5_0, Q5_1, NVFP4, Q1_0, Q2_0, the K-quants Q2_K to Q6_K of 256, the ternary TQ1_0 and TQ2_0, the IQ family) need the same view without that pairing: rows rows of cols / Block::elements blocks, end to end, over the caller's memory (host memory for opencl_quant.hpp, device memory for cuda_quant.hpp). BitNet's I2_S tensors, whose one scale is not in a block, are i2_s_weights.

// 4 rows of 1024 inputs: 4 blocks a row, 16 in all, row by row
std::vector<block> blocks(16);
const snicholls::gpu::block_weights<block> w{blocks, 4, 1024};
const auto third = w.row(2); // blocks 8 to 11

Relationships. opencl_quant.hpp and cuda_quant.hpp (the products over it), core's ml/quantize.hpp, ml/quant_k.hpp, ml/quant_ternary.hpp (the blocks, their quantisers and dequantisers). Group: snicholls-gpu. It stands in for a generic view in core, where it belongs once core has one.

Guarantees. Trivially copyable, two words and the shape; owns nothing.

Errors. None here; the products check the shape (cols a multiple of the block, the span's size) and throw std::invalid_argument.

Performance. Not benchmarked: a view.

Tests and demos. tests/quant_weights_test.cpp, demos/quant_weights_demo.cpp.

Dependencies. <cstddef>, <cstdint>, <span>.

Status. Experimental, new in 0.9.0.
