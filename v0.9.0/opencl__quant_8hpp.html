Detailed Description

snicholls::gpu::opencl_quant_kernels: matrix products whose weights stay in core's quantised formats on an OpenCL device, dequantised in registers, forward and backward to the input (inference and QLoRA fine-tuning).

Overview. A quantised model keeps its weights in blocks of a few bits (ggml's Q8_0, Q4_0 and MXFP4, ml/quantize.hpp; QLoRA's NF4, ml/nf4.hpp; or dense 8- and 16-bit floats, ml/minifloat.hpp). Dequantising a whole matrix before each product costs its float copy in memory and in bandwidth; these kernels read the blocks themselves and dequantise each weight in registers as the product needs it, as llama.cpp's do. Core's operations are overloaded for opencl_quant_backend (found by argument-dependent lookup), so core's ml::lora_sequence and ml::lora_sequence_backward run a QLoRA layer with its frozen base on the device:

  • linear_sequence(b, w, xs, ys, bias): Y = X Wᵀ + b for n rows of float activations.
  • linear_sequence_backward_input(b, w, dys, dxs): dX += dY W, the input's gradient through the frozen base (there is none to the weights: they are frozen).
  • linear_sequence_q8(b, w, xs, ys, bias): the integer path: each row of X quantised on the device to the 8-bit blocks core's dot product pairs the format with (Q8_0 for Q8_0, Q4_0, MXFP4 and Q5_0; Q8_1 for Q4_1 and Q5_1; Q8_K for Q2_K to Q6_K, TQ1_0 and TQ2_0), each output core's block dot product (ml::dot), as ggml's CPU matrix-vector products and core's ml::linear do.

w is one of core's views over host memory (ml::quantized_weights<Block>, ml::nf4_weights, ml::dense_weights<S> for bfloat16, float16, float8_e4m3 or float8_e5m2) or a block_weights<Block> of Q4_1, Q5_0, Q5_1, NVFP4, Q1_0, Q2_0, Q2_K to Q6_K, TQ1_0, TQ2_0, the IQ family (IQ1_S, IQ1_M, IQ2_XXS, IQ2_XS, IQ2_S, IQ3_XXS, IQ3_S, IQ4_NL, IQ4_XS), or BitNet's I2_S as an i2_s_weights (where the pinned core has them), copied to the device for the call, or an opencl_quant_matrix, the same weights kept on the device by opencl_quant_kernels::upload (frozen weights: upload once, multiply many times). The activations are host memory, copied for each call, as opencl_backend's products do.

// The kernels, built once for the context's device; the backend carries both
auto built = gpu::opencl_quant_kernels::create(*context);
if (built.is_err()) {
std::printf("opencl_quant demo: FAILED - the program did not build\n%s\n", built.unwrap_err().log.c_str());
return 1;
}
const auto kernels = std::move(built).unwrap();
const gpu::opencl_quant_backend device{{context.get()}, kernels.get()};
// Q4_0 weights, quantised by core; kept on the device, 4.5 bits a weight
std::vector<ml::block_q4_0> blocks(rows * cols / 32);
for (std::size_t i = 0; i < rows; ++i)
ml::quantize(std::span<const float>(w.data() + i * cols, cols), std::span<ml::block_q4_0>(blocks.data() + i * cols / 32, cols / 32));
const ml::quantized_weights<ml::block_q4_0> q4{blocks, rows, cols};
const gpu::opencl_quant_matrix on_device = kernels->upload(q4);
// Decode (one token: the matrix-vector kernel), prefill (64 tokens: the tiled kernel), the input's gradient
std::vector<float> y1(rows), ys(n * rows), dx(n * cols, 0.0f), yq(rows);
gpu::linear_sequence(device, on_device, std::span<const float>(x).first(cols), y1);
gpu::linear_sequence(device, on_device, x, ys);
gpu::linear_sequence_backward_input(device, on_device, dy, dx);
// The integer path: the token quantised to Q8_0, ggml's dot products
gpu::linear_sequence_q8(device, on_device, std::span<const float>(x).first(cols), yq);

Relationships. opencl.hpp (the context, and opencl_backend, whose dense products the LoRA adapters take), cuda_quant.hpp (the same kernels on CUDA, from the same source), core's ml/linear.hpp, ml/quantize.hpp, ml/nf4.hpp, ml/lora.hpp (the operations overloaded and the references). Group: snicholls-gpu.

Implementations. One source for OpenCL and CUDA (detail/quant_source.hpp): a format is one device function giving the weight at (row, column), decoded with core's arithmetic.

  • Matrix-vector (decode, at most opencl_quant_kernels::matvec_max rows, 8 by default): a work-group of 64 per four outputs, sharing each vector load of x; each item decodes eight consecutive columns at a time (a block's scale once), then the 64 partial sums of each output are added by a fixed tree.
  • Tiled (prefill, the backward): 64 x 64 tiles, 16 deep, the weights dequantised into local memory as the tile is loaded, 16 x 16 items of 4 x 4 outputs, each output summed in index order: the bits of core's reference product over the dequantised matrix (linalg::reference, then add_bias_rows, as ml::linear_sequence does).
  • Q8_0 activations: a thread per block of 32 quantises (core's quantize<block_q8_0>); a work-group per (output, row) computes core's per-block terms in integers and adds them in block order.

Guarantees. Deterministic: no atomics, every sum in a fixed order, so two runs give the same bits.

operation against bound
tiled forward and backward core's reference product over dequantized weights to the bit

| matrix-vector | the same | |Δ| ≤ k 2^-23 Σ_j |w_j x_j| per output (the classical bound of a reordered sum) | | Q8_0 activations | ml::linear(w, prepare_input(w, x), y, bias) | to the bit where the device divides correctly rounded (exact_q8()) |

On a device that flushes subnormal floats, the bits hold away from them. Weights and activations are not modified. One opencl_quant_kernels serves any number of threads (its kernel arguments are set under a mutex); it and every opencl_quant_matrix must not outlive the context.

Errors. create returns an opencl_failure when the program does not build. A shape the format does not allow (columns not a multiple of the block; spans of the wrong size) throws std::invalid_argument; Q8_0 activations with weights of another format, std::invalid_argument; a backend without kernels, std::logic_error; a failed OpenCL call, opencl_exception.

Performance. benchmarks/opencl_quant_benchmark.cpp, transfers included. First numbers, an AMD Radeon Pro Vega II (32 GB HBM2, macOS 26, Apple OpenCL 1.2, Release, 2026-11-20): see docs/performance.md.

Tests and demos. tests/opencl_quant_test.cpp (every format, every path, against core's references; the edge cases; determinism; a QLoRA layer through core's lora_sequence), demos/opencl_quant_demo.cpp.

Dependencies. opencl.hpp, detail/quant_source.hpp, core's ml/linear.hpp, ml/nf4.hpp, ml/quantize.hpp, ml/minifloat.hpp, <algorithm>, <array>, <cstddef>, <memory>, <mutex>, <span>, <stdexcept>, <string>, <vector>.

Known issues. PoCL 6 keeps a program's build files under its cache directory at paths given by the program, so processes that build the same program at the same moment can load each other's half-written kernels: build it once before starting many processes (the tests do, in a CTest fixture). BitNet's TL1 and TL2 are lookup-table tilings of the same ternary weights shaped for CPU SIMD kernels; on a device the weights are read as I2_S. OpenCL 1.2 has no integer dot instructions or tensor cores: everything is in float and int32 on the vector units. The device's division is correctly rounded only where it says so (CL_FP_CORRECTLY_ROUNDED_DIVIDE_SQRT); elsewhere a Q8_0 scale can differ from core's in its last bit.

Status. Experimental, new in 0.9.0.
