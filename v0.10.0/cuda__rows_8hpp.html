Detailed Description

snicholls::gpu::cuda_rows_kernels: the key-value cache's operations on CUDA, from the source opencl_device.hpp builds for OpenCL (detail/rows_source.hpp), so a forward pass over new tokens is written once against core's backend concept and runs on both.

Overview. cuda_ops.hpp already overloads core's row operations for cuda_training_backend (norms, RoPE, attention within a sequence, the MLP's activations); a pass over new tokens against a cache needs two more, kv_store_rows and attention_attend_cached_rows, and a third for weights core's linear_heads does not take, heads_from_rows (their host reference is in the consumer's model until core has them). This header compiles those kernels from the shared source with NVRTC and overloads the two operations for cuda_training_backend, found by argument-dependent lookup as opencl_device.hpp's are for opencl_device_backend. CUDA's device pointers are real, so every buffer offset is 0.

gpu::cuda_training_backend b{{context.get()}, kernels.get()};
b.rows = rows.get();
constexpr ml::transformer_config cfg{.d_model = 32, .n_heads = 4, .n_kv_heads = 2, .head_dim = 8, .d_ff = 48, .norm = ml::norm_kind::rms,
.norm_eps = 1e-5, .mlp = ml::mlp_kind::swiglu, .rope = ml::rope_kind::half, .rope_base = 10000};
constexpr std::size_t cap = 16, first = 6, n = 4, qn = cfg.q_size(), dh = cfg.head_dim;
snicholls::stats::wyrand g(2026);
std::vector<float> keys(cfg.n_kv_heads * cap * dh), values(keys.size()), q(n * qn);
for (auto* v : {&keys, &values, &q})
for (auto& x : *v)
x = float(snicholls::stats::uniform_real(g)) - 0.5f;
gpu::device_buffer<float> dk(*context, keys.size()), dv(*context, values.size()), dq(*context, q.size()), dy(*context, n * qn),
dl(*context, n * cfg.n_heads);
dk.upload(keys), dv.upload(values), dq.upload(q);
gpu::attention_attend_cached_rows<cfg>(b, std::span<const float>(dq.span()), std::span<const float>(dk.span()), std::span<const float>(dv.span()),
first, n, cap, dy.span(), dl.span());
std::vector<float> y(n * qn);
dy.download(y);

Relationships. opencl_device.hpp (the same operations on OpenCL), cuda_ops.hpp (the backend, its other operations), detail/rows_source.hpp. Group: snicholls-gpu.

Implementations. One kernel source for both APIs.

Guarantees. As opencl_device.hpp's: the cache's writes exact; attention in core's order (keys in tiles of 64, each scored by one thread with a sequential dot product, folded in key order), differing from the host only by the device's expf and logf. Deterministic.

Errors. create returns a cuda_failure when NVRTC or the load fails (the log on stderr); a launch that fails throws cuda_exception; a cache write or read past its capacity throws std::invalid_argument; a backend without rows throws std::logic_error.

Performance. Not yet run on an NVIDIA GPU: compiled without the toolkit (clang's NVPTX target, and the host code against the CUDA 12.9 headers); measured against OpenCL when the NVIDIA machine returns.

Tests and demos. tests/cuda_rows_test.cpp, demos/cuda_rows_demo.cpp (where CUDA is).

Dependencies. The CUDA runtime and NVRTC, cuda_ops.hpp, detail/quant_source.hpp (the CUDA prelude), detail/rows_source.hpp.

Known issues. Heads of at most 128 channels.

Status. Experimental. CUDA: not yet run on an NVIDIA GPU.
