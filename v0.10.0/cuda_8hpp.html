Detailed Description

snicholls::gpu::cuda_backend: a snicholls::linalg::blas_backend on an NVIDIA GPU through cuBLAS, over device memory in place or host memory staged.

Overview. The NVIDIA backend, beside the portable OpenCL one: cuBLAS for the matrix products, and device memory that core's views point at directly. CUDA tells a device pointer from a host pointer at run time, so one backend takes both:

  • device memory (device_buffer<T>, whose span() is a std::span over it) is used in place: a training step's weights and activations stay on the GPU between products;
  • host memory is staged: copied up, multiplied, the result copied back, as the OpenCL backend does.
  • cuda_context::create(device): the device, its cuBLAS handle and stream; result with a cuda_failure when there is no device.
  • cuda_backend{&context}: the backend, a pointer and cuda_math (float, or TF32 on the tensor cores), trivially copyable as the concept requires. gemm and gemv run on the device; dot, axpy, syrk and triangular_solve run on the host through core's reference, for host memory (device memory there throws, until those move to the device).
  • device_buffer<T>: n elements of device memory; upload, download, span().
  • cuda_graph::capture(context, f): the work f queues on the context's stream as a CUDA graph, launch()ed again as one launch (a training step's thousands of kernels).
auto made = gpu::cuda_context::create(); // device 0: its cuBLAS handle and stream
if (made.is_err()) {
std::printf("cuda demo: FAILED - no CUDA device\n");
return 1;
}
const auto context = std::move(made).unwrap();
const gpu::cuda_backend device{context.get()};
constexpr std::size_t n = 128, d = 256, out = 512;
std::vector<float> x(n * d), w(out * d), from_host(n * out), reference(n * out);
for (std::size_t i = 0; i < x.size(); ++i)
x[i] = static_cast<float>(i % 13) * 0.1f - 0.6f;
for (std::size_t i = 0; i < w.size(); ++i)
w[i] = static_cast<float>(i % 7) * 0.05f - 0.15f;
const la::matrix_view<const float, right> xv(x.data(), {n, d}), wv(w.data(), {out, d});
// From host memory: staged to the device and back, as any backend
const auto staged = la::gemm(device, 1.0f, xv, la::transposed(wv), 0.0f, la::matrix_view<float, right>(from_host.data(), {n, out}));
// From device memory: the operands stay on the GPU; core's views point at it (never read on the host)
gpu::device_buffer<float> dx(*context, x.size()), dw(*context, w.size()), dy(*context, n * out);
dx.upload(x);
dw.upload(w);
const auto resident = la::gemm(device, 1.0f, la::matrix_view<const float, right>(dx.span().data(), {n, d}),
la::transposed(la::matrix_view<const float, right>(dw.span().data(), {out, d})), 0.0f,
la::matrix_view<float, right>(dy.span().data(), {n, out}));
std::vector<float> from_device(n * out);
dy.download(from_device);

Relationships. snicholls/core/linalg/backend.hpp (the concept), core's linalg::reference (the reference the results are checked against) and its conformance suite; opencl.hpp (the portable backend, the reference's bits). Group: snicholls-gpu.

Implementations. gemm maps each view onto cuBLAS's column-major storage without copying when it is row- or column-major (a row-major C is computed as Cᵀ = Bᵀ Aᵀ); any other strides are packed into a contiguous copy on the device. cuBLAS's default math in float and double (no TF32): its own order of summation, so results agree with the reference to rounding, not to the bit.

Guarantees. One context serves any number of threads (one mutex per context around the handle and the stream). A product whose operands and result are all device memory is queued on the context's stream and returns at once: it is ordered before everything later on that stream (cuda_ops.hpp's kernels, the next product) and before a device_buffer::download; cuda_context::synchronize() waits for it, for anything else (another context's stream) that reads it. A product that touches host memory has finished, its result in place, when it returns. The context owns the handle and the stream; a backend must not outlive it, nor a device_buffer its context.

Errors. cuda_context::create returns a cuda_failure (no device, or a CUDA or cuBLAS call failed, with its code). A call that fails on the device (out of memory, a lost device) throws cuda_exception, a std::runtime_error with the code; so does a host-only operation handed device memory.

Performance. benchmarks/cuda_benchmark.cpp, against the OpenCL backend and core's reference, transfers included for host memory and none for device memory: see BENCHMARKS.md.

Tests and demos. tests/cuda_test.cpp (core's linalg BLAS conformance suite, the reference's results to rounding for every shape and layout, device memory in place, strided views, threads), demos/cuda_demo.cpp. Built only where CUDA is (SNICHOLLS_GPU_WITH_CUDA).

Dependencies. <cstddef>, <memory>, <mutex>, <stdexcept>, <string>, <type_traits>, <vector>, <cuda_runtime.h>, <cublas_v2.h>, snicholls/core/linalg/reference.hpp, snicholls/core/result.hpp. Link CUDA::cudart and CUDA::cublas (the target snicholls::gpu_cuda).

Known issues. Tensor cores (TF32, bfloat16) are not used yet; they are the next step, with a stated tolerance.

Status. Experimental, new in 0.2.0.
